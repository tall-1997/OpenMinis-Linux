# 1.36.23-linux

versionCode **76**。安装包 `minis-ultra-com.openminis.linux.apk`。包名 `com.openminis.linux`，可与官方 OpenMinis 并排安装。

相对 1.36.22-linux。这一版修的是从更低版本升上来会丢数据、装不上包，或把一次失败记成永久状态的问题。

## 升级不覆盖已有数据

- 跳过 1.36.13 的设备没有 `force_overwrite_1_36_13`。以前第一次启动会把 `SOUL.md` 整文件换成出厂人格。现在只补标记，不改已有文件。仍是出厂四行模板的，继续替换成当前模板。
- 技能开关以前只写在数据库里。空的偏好集合会被当成「没关过」，启动时把关掉的技能全部重新打开。第一次升级会把数据库里已关闭的 id 抄进偏好。
- 旧版 Ubuntu 根文件系统只有 `.arch`。当前版会把它当成没装过，删掉整个沙箱，包括 `/root` 和已装软件包。架构匹配且 `usr/bin` 或 `bin` 还在时，补上 `ubuntu-noble`，不再重装。
- Node 的「已经试过」标记改到安装结束之后再写。锁或网络失败会在下次启动重试。仓库里确实没有这个包时才记下来，避免每次启动都再装一次。

## 安装、锁和超时

- 等待 apt 锁最多 5 分钟。已经开始的安装不会在第 5 分钟被取消，也不会在客户机 apt 还在跑时放掉宿主锁。
- 客户机锁用 `mkdir` 加 pid。活着的持有者不会因为目录太旧被清掉。释放时只删自己的锁。拿不到锁时安装以退出码 1 结束。
- `minis-dev-setup` 被中断时会放开锁再退出。`minis-dev-setup-full`、`minis-android-sdk-setup`、`minis-self-build` 的超时下限是 30 分钟。

## 工作区、下载和命令

- 空目标上的搬移失败不再把私有文件藏进看起来是空的项目目录。中断的搬移下次启动接着做。原子写不再先删目标再改名。
- 应用内更新遇到 HTTP 416 时，分片长度必须和发布包一致才算下完。更短的分片会丢掉，不会装成残缺 APK。
- 会话路径被拒绝后，读图和模型调用不再改去读全局绑定目录。权限模式读的是生效值。
- 命令超时会杀掉本机进程。自编译在开始前登记活动状态，登记失败也不会把界面卡在「正在编译」。从当前界面打开媒体或分享，不再无条件把界面送回桌面。

## 安装

侧载前允许「安装未知应用」。debug 签名不能覆盖用另一张证书装上的版本，见 [docs/SIGNING.md](docs/SIGNING.md)。完整说明见 [docs/RELEASE-NOTES.zh.md](docs/RELEASE-NOTES.zh.md)。
